## 最も重大な 3 件

### 1. 領域なしの注記が入れられない（A1）

`design.md` §9.7 は「まとまり全体へのメモも、領域なしの注記として同じ表で扱う」と決め、契約はそれを受ける形（座標が null 可。実行で確認）になっているのに、設計の DDL は座標を `NOT NULL`、`POST` は座標が欠けると 422 で、「領域なし」の語が一度も出てこない。実装してから直すと表の作り直し（v5）になる。座標を NULL 可にして「全部 NULL か全部あり」を `CHECK` で縛るだけで済むので、今決めるのが安い。

### 2. 「開いて決める」の先の画面が存在しない（A2）

設計は「既存のまとまりレビュー（`#/group/<id>`）」へ飛ぶと書くが、P5 が作ったのは一覧・拡大・比較だけで、キープ / ボツを付ける画面は無い（`index.html:13` にそう書いてある）。合格の線 2「要求の一覧から開いて判断し、判断で閉じる」は、この設計の範囲では人が画面から判断できない。P6-1 にまとまりレビューの最小形を入れて段を割るか、線 2 を API で満たすと明記するか、どちらかを決めてから着手すべき。

### 3. 切り出しの式が幅によって 1 画素はみ出し、PNG の符号化が大きな囲みで目標の 2〜4 倍になる（B1 / B2。**実行して分かった**）

`ceil((x + w) * W)` は浮動小数の足し算のせいで、幅 1360 では 0.001 刻みの 3,170 組で 1 画素余計になる（1024 / 2048 では 0 組なので、§8.1-13 のテストでは見つからない）。`round(…, 6)` を挟めば 0 組。また、PNG の保存は切り出しの画素数に比例し、1024² 全面で 66 ms、2048² 全面で 320 ms と §7 の 30 / 80 ms を大きく超える。目標を画素数比例に書き直し、`compress_level=1`（無劣化のまま 3 倍速い）を決めておく。
