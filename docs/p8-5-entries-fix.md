## 1. 直したこと

### 1.1 `#/duplicates`（重複の整理）への入口が画面に 1 つも無かった

- 症状: `apps/gui/index.html` に `href="#/duplicates"` が **0 件**。画面（`#duplicates`）も道（`app.js` の
  `duplicating`）も在るのに、**URL を打たないと入れなかった**。
- 根拠: `frontend-design.md` §3 の 6（重複の整理は「重複を整理して本当に消す」の入口）・§5・§11。
  置き場は `#/jobs` の隣ではなく**上部バー**（P8-3 の点検 B5 の決着。`p8-review-triage.md` G7）。
- 直し方: 上部バーの**右端（`設定` の隣。`spacer` の後ろ）**に常設の入口を置いた。
  ```html
  <a class="back set-open" id="stat-duplicates" href="#/duplicates">重複の整理</a>
  ```
  - **`set-open` を足した理由**: `.back` は画面ごとの CSS（`#duplicates .topbar .back` など）にしか
    無く、ライブラリの上部バーでは**素のリンク**（下線・青）になる。`設定` と同じ `set-open` を付けて
    「押せる物」と同じ見た目にした（見た目は写真で確認。§4）。
  - **出る条件は無い**（いつでも押せる）。押しても道が変わるだけで `GET` も `POST` もしない。
- 設計に書き足した先: §3 の箇条書き・§4.5.1 の「右端に常設の入口を 2 つ」・§6 の文言の行・§11 の行。

## 6. 自分で決めた点（設計が黙っていた所）

1. **入口の件数は「返ってきた行の数」**（`GET /api/pending-deletes` の `items` の数＝`count`）。
   段 2（ゴミ箱）の行も数える（画面に出ているため）。窓の無い行には**残り時間を出さない**。
2. **`stuck` だけでも入口を出す**（画面で「別名で戻す」を押せるため）。前の検査は「戻せない物だけなら
   出さない」だったが、**画面に出ている物への入口を隠す**方が辻褄が合わないと判断した。
3. **入口の見た目は `設定` と同じ `set-open`**（`.back` はライブラリの上部バーでは当たらない CSS だった）。
4. **`gui_smoke` の既存の期待値を 2 つ変えた**（`最近の削除 2 ・ あと 0:10` → `最近の削除 5 ・ あと 0:10`、
   「戻せない物だけなら出さない」→「戻せなかった行だけでも出す」）。**検査を緩めたのではなく、
   設計（§4.6 の「1 行 = 台帳の 1 行」）に合わせた**。
5. **`design.md` は触らず**、文言の正は `frontend-design.md` §6 に置いた（親の指示）。

## 8. 設計の穴（次に直す人へ）

- **`frontend-design.md` は「入口」を §3・§4.5.1・§4.6・§11 の 4 か所に分けて書いている。**
  今回のように**常設の入口**を足すと 4 か所を直すことになる（1 か所に表が欲しい）。
- **`gui_layout` の窓は 1200 以上しか無い**（`VIEWPORTS` は 1400/1200/1920 の固定）。
  `--viewport` は**一覧を絞るだけ**なので、`--viewport 768x1360` は**何も見ずに「すべて ok」と出る**
  （今回それで一度空振りした）。狭い窓（768）は今回**自前の Chrome 検査**で見た（はみ出し 0）。
  直すなら `VIEWPORTS` に 768x1360 を足すか、`--viewport` を「一覧の追加」にする。
- **`gui_smoke` はリンクを辿れない**（作り物の DOM にページ遷移が無い）。入口の検査は
  「`href` が正しいか」までで、**押して画面が出るかは Chrome でしか見られない**（今回はそう書いた）。
