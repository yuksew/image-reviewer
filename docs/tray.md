## 0. 何を作ったか

```text

  └ image-reviewer-tray.cmd       # トレイの実体（入口）
       └ powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden `
                    -File tools\tray.ps1 -Port 8790
            ├ GET /api/health で「誰か居るか」を確かめる
            ├ 誰も居なければ .venv\Scripts\python.exe -m image_reviewer.cli serve --port 8790 を
            │    **子プロセス**として起動（**IMAGE_REVIEWER_DATA を明示して渡す**＝監査 A-1。
            │    ログは .tray\server.log / server.err.log。前の 1 世代は *.prev.log）
            ├ NotifyIcon を**メインスレッド**で回す（5 秒ごとに /api/health・/api/review-requests・
```

## 1. 使い方

### 1.1 起動

| 起動 | 何が起きるか |
| --- | --- |
| デスクトップの `image-reviewer.lnk`（＝`start-image-reviewer.cmd`） | トレイで立ち上がり、ブラウザが開く |
| `image-reviewer-tray.cmd` をダブルクリック | 上と同じ |
| `start-image-reviewer-console.cmd` | いままでどおり（黒い窓にログ。窓を閉じるとサーバも止まる） |

- **2 回目に起動しても、トレイは 1 つだけ**（`Mutex` で見張る）。2 回目はブラウザを開いて終わる。
- **既に動いているサーバがあれば二重に起動しない**（`GET /api/health` が
  `app: "image-reviewer"` と答えたら、それに繋ぐ＝`attach`）。
- **別のアプリがポートを使っていたら起動しない**（相手を止めない・黙って別のポートへ移らない）。
  ダイアログで「ポート 8790 は別のアプリが使っています。このトレイは起動できません。
  `image-reviewer-tray.cmd` の `-Port` を変えてください。」と出す。

### 1.2 メニュー（アイコンを右クリック。5 つ）

| 項目 | 何が起きるか |
| --- | --- |
| **ブラウザで開く** | `http://127.0.0.1:8790/` を既定のブラウザで開く（**アイコンのダブルクリックでも同じ**） |
| **最近の削除を開く** | `http://127.0.0.1:8790/#/pending-deletes` を開く（`frontend-design.md` §11 の入口 (c)） |
| **状態を見る** | 小さな窓を開く（§1.4） |
| **再起動する** | **自分が起動したサーバだけ**止めて、起動し直す（落ちていれば「起動する」に変わる） |
| **終了する（サーバも止める）** | サーバを止めてトレイを閉じる |

- **既に動いていたサーバに繋いだとき**は、最後の 2 つが変わる:
  「**トレイを閉じる（サーバは止めない）**」になり、「再起動する」は**押せない**
  （理由は `title` に「既に動いていたサーバなので、このトレイからは止められません。」）。
  **押す前に何が起きるか分かる**ようにしてある（`frontend-design.md` §6.1 の規約 3）。

### 1.3 見え方（アイコン・ツールチップ・知らせ）

- **アイコンの形は 4 通り**（`design.md` §4.1。**件数は出さない**）:
  **ふつう** / **要求あり**＝`--accent` の印 / **取り消せる削除あり**＝`--warn` の印 /
  **両方**＝枠が `--accent` で印の縁が白。**バックアップに失敗している間は枠が `--drop`（赤）**。
  **停止中は「ふつう」と同じ枠色ではなく、× の印を描く**（16 px では色だけでは区別できない＝監査 B-2）。
- **印が数える「取り消せる削除」は段 3（5 分の窓がある行）だけ**（監査 G-1(b)。段 1 の行は
  片付けても消えないので、全部を数えると実データでは常に点いてしまう）。**ツールチップと
  状態の窓は今までどおり全部の数**を出す。
- **ツールチップ**（63 字まで）: `image-reviewer（稼働中）、要求 3、最近の削除 12`。
  中黒「・」は名詞の対にだけ使う決まりなので、**メタ情報は読点で繋ぐ**（§6.1 の規約 1）。
  バックアップに失敗していれば `、バックアップに失敗しています` が必ず付く。
  **口が時間切れの回は `、件数を確かめられません`** を足し、数は前の回の値を出す（監査 C-2）。
- **知らせ（バルーン。音は使わない）**: 変わったときに**1 つだけ**出す。
  ①**バックアップに失敗しています**（最優先。**起動の直後の 1 回でも出す**＝監査 C-1）
  ②エージェントから要求が来ました（N 件）③取り消せる削除があります（N 件。**段 3 の数**）。
  **自分が起動したサーバが落ちたら「サーバが止まりました。トレイの「起動する」で起動し直せます。」**
  （監査 B-2。他人のサーバが落ちても知らせない＝自分は止めていない）。
- **見る周期**: 5 秒（画面の上部バーと同じ）。**サーバが落ちている間は 15 秒**に延ばす
  （この環境は「誰も居ないポートへの接続」に約 2 秒かかるので、5 秒ごとに固めない）。
  **1 周期の 4 つの口はそれぞれ 2 秒で見切る**（監査 C-2。5 秒 × 3 で UI が 15 秒止まっていた）。
  **1 つでも時間切れなら残りを打たず**、前の値に「（確かめられませんでした）」を付けて出す。

### 1.4 「状態を見る」の窓

```
image-reviewer 0.0.1-proto（稼働中）

アドレス: http://127.0.0.1:8790
データ置き場: C:\work\image-reviwer\.data
要求: 3 件
最近の削除: 12 件（あと 3:12）

バックアップの保存先: C:\work\image-reviwer\.backup\daily
最後に取った時刻: 2026-10-19 02:31
今日の分はまだです（30 秒ごとに見ています）
取ってある世代: 3

この窓は読むだけです。操作はトレイのメニューから行います。
```

- **バックアップに失敗していれば必ず出す**（家風「黙って失敗しない」）。**失敗の全文**もここに出す:
  `バックアップに失敗しています（2026-10-19 03:00）。` ＋ `DB がいま混んでいます（database is locked）`。
  **本文が取れなかったときは口の名前と HTTP の番号を出さない**（`（理由は取れませんでした。詳細: 503）`＝監査 D-2）。
- **読み取り専用で起動している**ときは「読み取り専用です。」＋理由を出す。
- サーバが落ちていれば「**サーバに繋がりません。**トレイの「**起動する**」で起動できます。」——
  **そのときのメニューの語と同じ**にする（監査 D-1。落ちているとメニューは「起動する」に変わる）。
- **ポートに居るのがこのトレイの起動した物でない**とき（自分のサーバが落ちて他人が立った形）は
  「いまポートに居るのは、このトレイが起動したサーバではありません。再起動と終了では、そのサーバを
  止めません。」と出す（監査 C-4）。
- 時刻は**現地の `2026-10-19 02:31`**（§6.1 の規約 1。サーバは ISO で返すので `Format-When` で直す）。
- 窓は**読むだけ**。閉じるボタンは「閉じる」。

### 1.5 終了

- メニューの「**終了する（サーバも止める）**」で、**自分が起動したサーバを木ごと止めて**から閉じる
  （`tools/tray_selftest.ps1` の §9 は関数の道、§9b は**メニューの終了の道**を通す＝監査 F-4）。
- **止められなかったときは黙って終わらない**（ダイアログで「サーバを止められませんでした。少し待ってから、
  もう一度終了してください。」と出す）。**「タスクマネージャーで python を終わらせて」とは言わない**——
  止められなかった相手が他人のサーバだと、その案内は**他人を止めさせる**（監査 C-4）。
- **既に動いていたサーバは止めない**（そのときはメニューの語が変わる）。

### 1.6 記録

`<リポジトリ>\.tray\` に 3 つ（**`.data` には 1 バイトも書かない**）:

| ファイル | 中身 |
| --- | --- |
| `tray.log` | トレイの判断（起動・繋いだ・止めた・知らせ・状態の窓の本文） |
| `server.log` / `server.err.log` | サーバの標準出力と標準エラー（**起動のたびに作り直す**） |

- **前の 1 世代を `*.prev.log` に残す**（監査 D-6。落ちた理由が「起動する」の 1 押しで消えない）。
- **既定の 8790 以外のポートでは `server-<ポート>.log` / `server-<ポート>.err.log`** に分ける
  （監査 D-8。別のポートの 2 つが同じファイルを取り合うとログが混ざる）。
- 子には **`PYTHONUNBUFFERED=1`** を渡す（監査 D-7。走っている間のログがブロック単位で溜まって空に見える）。

  持っている子は片付ける）・R11（他人が立った形では再起動しない）＋
  **A-1 の振る舞いの検査**（`tests/test_tray_ports.py`。本物の自己検査を子で回す）。

1. **一瞬だけ黒い窓が出ることがある。** `-WindowStyle Hidden` で隠すが、`.cmd` から
   `powershell.exe` を起こす一瞬は消せない（`design.md` §4.1 の表に既知の穴として書いた）。
   完全に消すなら `.vbs`（`WScript.Shell.Run` を 0 で呼ぶ）だが、**ファイルをもう 1 つ増やす**ので
   いまは作っていない。
2. **終了は `taskkill /F`（強制）**（G-2 の推奨どおり**このまま持ち越す**）。Windows なので
   「お願いして止める」道が無く、**終了時の書き出し（`export/groups/*.json` の溜まっている分）は
   走らないことがある**。ただし `export.py` は**起動時に溜まっている分を書く**（`exporter.flush_dirty()`）ので、
   **次の起動で追い付く**（失われない）。uvicorn の lifespan を丁寧に通したいなら、
   将来 `POST /api/shutdown` のような口を作る話になる（**いまは作っていない**。
   トレイは `src/` を触らない方針）。
3. **サーバが落ちている間は、見張りが最大 2 秒 UI を止める**（この環境の接続拒否が
   約 2 秒かかるため）。15 秒に延ばして緩めたが、**ゼロにはしていない**（背景スレッドに逃がす
   実装はまだ無い）。**生きていて遅いときの 15 秒は C-2 で塞いだ**（4 つの口を 2 秒で見切る）。
4. **「状態を見る」の窓はモーダル**（開いている間はメニューを押せない）。読むだけの窓なので
   実害は無いが、**要件ではない**。
5. **アイコンの形は 4 通り + 失敗時の枠色 + 停止中の ×** で、**8 通りを全部は弁別できない**
   （バックアップ失敗中は「削除あり」と「両方」の枠が同じ赤になる。**ツールチップが両方の情報を
   常に出す**ので、そちらで分かる）。**段 1 だけの削除では印が点かない**（意図した仕様。段 1 は
   ツールチップと状態の窓の数で分かる）。
6. **トレイそのものの二重起動は `Mutex` で防ぐが、`Mutex` は「同じポート」の単位**。
   別のポートで 2 つ目のトレイを立てることはできる（テストではそれを利用している）。
7. **P10 の「ファイルが無いので片付ける」はトレイから使えない**（画面だけ）。
   入れるかどうかは利用者の判断（`handoff.md` §3 の 2）。**G-3 の推奨どおり入れない**
   （トレイは「開く・知る・止める」に留める。確認の画面を持てない）。
8. **ブラウザを開くときに URL を検証していない**（`Start-Process <url>` に渡すだけ）。
   ポートは自分が決めた数値なので、外部入力は入らない。
9. **`-DataDir` を渡さない本番の道は、既定の `<リポジトリ>\.data` を明示して開く**（A-1 の直し）。
   利用者が `IMAGE_REVIEWER_DATA` を別の置き場に向けていても、**トレイは `.data` で起動する**
   （コンソールの起動とは振る舞いが違う＝監査 E-4）。**わざとそうしている**——「親の環境に任せる」形に
   戻すと、A-1 と同じ事故（既定の `.data` を開く）が起きる。将来 `-DataDir` を利用者向けの設定に
   するなら、`image-reviewer-tray.cmd` に 1 行足す形にする。
10. **踏み台（`.venv\Scripts\python.exe`）が先に終わって本体だけが残ると、そのサーバは「自分の物」に
    できない**（**再確認で気づいた穴**）。`Start-OwnServer` は踏み台が終わっていたら即失敗し
    `Proc` を手放すので、**遅れて port を掴んだ本体は迷子**になる（親の PID は既に死んでいて
    親子をたどれない）。**確かめられないので止めない**（迷ったら止めない）。実際には踏み台は
    本体の終了まで待つので起きにくいが、**ポートに残ると次の起動が `attach` になる**。
    直すなら「`/api/health` の `data_dir` が自分が渡した置き場と一致し、かつ起動の直後に現れた」
    ことを条件にする形（**今回は入れていない**。頻度が読めないため）。

## 5. 環境の罠（この環境で実際に踏んだ物）

| 罠 | 実測 | どうしたか |
| --- | --- | --- |
| **`.ps1` が素で実行できない** | `& .\tools\tray.ps1` は「not digitally signed」で断られる。`-ExecutionPolicy RemoteSigned` でも `Unrestricted` でも断られ、**`Bypass` だけが通った**（3 通りを実測） | `.cmd` と検査の呼び出しに**必ず `-ExecutionPolicy Bypass`** を付ける |
| **`.ps1` は UTF-8 の BOM 付きで保存する** | BOM を外すと PowerShell 5.1 が cp932 として読み、日本語の文字列が壊れて**構文エラー**（`.tmp-tray\drive_browser.ps1` が実際にこれで落ちた） | 保存のたびに BOM を確かめる（`tests/test_tray.py` が見張る）。`.cmd` は**BOM 無し**（cmd.exe が先頭行を誤解する）＋ CRLF |
| **編集の道具で `.ps1` を書き換えると BOM が落ちる** | `edit` で 1 行直しただけで BOM が消え、次に走らせた検査が**cp932 として読んで構文エラー**（今回 4 回踏んだ） | 書き換えたら**必ず BOM を付け直す**（今回の直しでは `.tmp-tray-fix\fix_bom.py`）。`pytest` の `test_the_powershell_scripts_are_utf8_with_bom` が最後の網 |
| **`.venv\Scripts\python.exe` は踏み台** | `Start-Process` が返す pid（踏み台。47 KB の exe）と `/api/health` が名乗る pid（本体）が**別**。木は 踏み台 → 本体 | **PID を 2 つ持つ**。止めるのは木ごと（`taskkill /T /F`）、確かめるのは両方。**親子は `Win32_Process.ParentProcessId` をたどって確かめる**（`uv run` はもう 1 段深い） |
| **誰も居ないポートへの接続が約 2 秒** | 生の `TcpClient` で 2015〜2052 ms（生きているポートへは 0 ms） | 待ちは 3 秒。落ちている間の見張りは 15 秒。**1 周期の 4 つの口は 2 秒で見切る** |
| **`$Pid` という引数名は使えない** | 「Cannot overwrite variable Pid because it is read-only or constant」で**検査が落ちた**（`$PID` は自動変数） | `-ProcessId` に改名 |
| **`Get-Process -Id 0` は Idle を返す** | 「掴めていない PID」を「生きている」と読み違える（検査が**空振りで ok** になった） | `Test-PidAlive` で 0 以下を偽にする |
| **UI スレッドが眠っている間は Timer が動かない** | 駆動の検査で `Start-Sleep 6` の間、見張りの刻みが動かず「要求を拾っていない」ように見えた | `Application::DoEvents()` で溜まったメッセージを処理させる |
| **サーバの起動時に `%USERPROFILE%` を作れない**（既知） | 複製で `backup_dir` を設定しないと日次が失敗する | 検査と駆動では `IMAGE_REVIEWER_BACKUP_DIR` を**複製の外**へ向ける（**わざと「フォルダでない物」を指して、失敗を読む道も通す**＝監査 F-3） |
| **`Start-Process` の子は親の標準出力を引き継ぐ** | 検査の出力がパイプに溜まり、**コマンドが終わったのに返ってこない**ように見えた | 検査が起こす子には**必ず `-RedirectStandardOutput` / `-RedirectStandardError`** を付ける |
| **検査が途中で例外で死ぬと、子のサーバがパイプを掴んだまま残る** | `Send-TrayNotifications` に `$null` を渡して検査が落ち、孤児のサーバ 2 つが残って**呼んだ側の PowerShell が 10 分戻らなかった** | 自己検査の先頭に **`trap`** を置き、落ちたときは**この検査のサーバ（`--port`〜`+3`）だけ**片付けて `exit 3` |
| **検査を回す前に、使うポートが空いているとは限らない** | 監査の再現では、ポートが埋まっていると §2 が `attach` になり、**環境変数の無い `cli serve`＝既定の `.data`** を起こした（A-1 の事故そのもの） | §1 で 4 ポートを確かめ、埋まっていれば**1 つも起動せず `exit 2`** |
| **カンマは `+` より強い**（再確認 A-1） | `@($Port, $Port + 1, $Port + 2, $Port + 3)` は **7 要素 `8795,8795,1,8795,2,8795,3`**（`count=7`）。**8796〜8798 を見ていなかった**ので、8796 に立っていた本物の複製サーバを §10 が止めた | **括弧を付ける**（`($Port + 1)`）。**4 つとも別**を §1 で数える。振る舞いは `tests/test_tray_ports.py` |
| **後始末を「ポートで探して止める」形にすると他人を巻き込む**（再確認 C-2） | §1 の後に他人がそのポートへ立てることはある（並行の監査・別の自己検査）。`--port <n>` の python を全部止める形は、それを殺す | **この検査が起こした PID の木だけ**を止める（`Register-OwnProcess` / `Stop-OurProcesses`）。`Wait-ServerUp` も `-Proc` で受ける |
| **駆動はトレイを丸ごと起こす**（再確認 B-1） | `-DriveScript` に `-DataDir` を付け忘れると**本番と同じ道**で既定の `.data` を開く（写しのリポジトリで実測: `db.sqlite3-wal` ができた）。`tray_drive.ps1` は `POST` する | 試験用の引数を `$script:TestArgs` にまとめ、**入口と `Get-EffectiveDataDir` の両方**で断る |
