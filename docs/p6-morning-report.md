## あなたに決めてほしいこと（設計者が判断を保留した 3 件）

設計はいずれも**左の (i) を推奨**しています。Fable の意見も点検報告の `G` に入ります。

### (a) 切り出しの書き出しを `GET` で受けるか

- **(i)（推奨）`GET .../annotations/export` は `format=json` だけ**。`format=crops` を `GET` で来たら
  **422 で `POST` を案内**する。`POST` だけが PNG を書く。P5 で決めた「**`GET` は書かない**」に揃う。
- (ii) `design.md` §6.1 の字面どおり、`GET` でも書く（読み出しに副作用が戻る）。
- (iii) `GET` は**その場で作って返すだけ**にして、`<data>/annotations/` にファイルを残さない
  （他の道具に渡すには `POST` が要る）。

### (b) 要求の応答を保存するか、毎回導出するか

- **(i)（推奨）閉じた時点の写しを `response` 列に保存**。理由: まとまりは `reopen` できるので、
  導出にすると**エージェントが受け取った答えが後から黙って変わる**（P5 の「`reason_label` は
  書き出し時点のマスタ」と同じ問題）。
- (ii) 毎回まとまりの現在値から導出（列は増えないが、答えが後から変わる）。

### (c) 注記を消したとき、書き出した切り出しの PNG も消すか

- **(i)（推奨）残す**。他の道具に渡した後かもしれない。切り出しは**いつでも作り直せるキャッシュ**。
- (ii) 一緒に消す（`<data>/annotations/` が溜まらない）。
- (iii) 消すが、`#/settings` に一括削除を置く。

## 私（DeepSeek）が見つけた設計の直し（点検の後に反映します）

- **パスから画像を引く規則は、既存の `store.normalize_path()` を使うべき**です。設計の §0.10 は
  「比較のときだけ `casefold` と `/` → `\`」と書いていますが、`store.py:39` に
  **登録時と参照時で同じ鍵を作る関数**が既にあります（`os.path.normcase(os.path.realpath(...))`。
  ジャンクションも解決する）。`Store.location_by_path()`（`store.py:128`）が同じ鍵で引いているので、
  要求の受付もこれを使えば **ID で引いた場合とパスで引いた場合が必ず一致**します。
  → 設計の §0.10 の該当行と §10-1（「実機で確かめていない」）を書き換えます（未確認ではなく、
  既存の規則に乗るだけ）。
- 画面一覧の確認: **`#/requests` は `frontend-design.md` §3 の 5 番**（設計の主張どおり）。
- `actor` は **ヘッダ `X-Image-Reviewer-Actor` だけ**から取り、無ければ `agent`
  （`api/__init__.py:36`）。＝ **要求の受付は誰でも通る／`decline` と `decide` は 403** という設計の筋は
  既存の仕組みでそのまま実現できます。
