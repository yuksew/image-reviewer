## 1. この画面は何のためにあるか

| 項目 | 内容 |
| --- | --- |
| 使う人 | 1 人（この環境の持ち主）。イラストの生成と選別を自分で行う |
| 主な仕事 | **大量の候補を見て、キープ / ボツを素早く付ける。** そして「なぜ違うか」を読む |
| 副次的な仕事 | エージェントから来たレビュー要求に即応する。集めて探す。重複を整理する |
| 量 | 1 回に 10〜50 枚をさばく。たまった数百枚をまとめて見る回もある。総数 〜1 万枚 |
| 場面 | 生成を回した直後の夜。長い時間、画像の前に座り続ける |
| 画面の競合 | **絵が主役。** 画面の色は絵の色の判断を邪魔してはいけない |
| 言語 | 画面は日本語。Danbooru タグは英語（＋日本語の語釈） |
| 操作 | マウス中心。キーボードは**補助**（あれば速い、必須ではない） |

### 1.1 この仕事の性質から来る制約

1. **絵の色を正しく見せる必要がある。** 周囲の色が暖かいと、絵の色が冷たく見える。→ 画面の地色は**中立の灰**にする。クリーム色や青みの強い黒は使わない。
2. **1 枚あたりの判断は数秒。** 数百枚を回すので、1 枚ごとの装飾は積み重なって邪魔になる。→ カードの影・角丸・ホバー効果を使わない。
3. **「ボツ」が視界から消える必要がある。** 全部が同じ見た目だと、どれを落としたか思い出せない。→ 状態を**絵そのもの**に出す（彩度を落とす）。
4. **エージェントの要求は割り込む。** まとめて見ている最中でも、要求が来たら気づける必要がある。ただし強制的に画面を奪わない。

## 2. デザインプラン

### 2.1 題材から取る視覚の言語：ベタ焼き（コンタクトシート）とルーペ

この仕事の材料は「フィルムのベタ焼き」と「ルーペ」である。写真を選ぶ人は、ベタ焼きを台に並べ、
**ルーペで覗き、グリースペンシルで印を付ける**。この道具立てが、そのままこの画面の構造になる。

| 題材の物 | 画面での対応 |
| --- | --- |
| ベタ焼き（フレームが隙間なく並ぶ） | 一覧のグリッド。**行＝フィルム 1 本**として、行の中は隙間なく接する |
| フィルムの素地（黒い筋） | フレームの境目の 1px の筋（継ぎ目） |
| コマ番号 | フレームの番号（キーボードの `1`〜`8` と対応するので、装飾ではなく情報） |
| グリースペンシルの印 | キープの**楔**、ボツの**斜線**と彩度落とし |
| ルーペ | 拡大表示。全画面に近い、地色だけの空間 |
| 台の上の選別 | まとまりレビュー（フィルムストリップ＋大きな 1 枚） |

**この題材を選んだ理由**: 「多数の似た絵から選ぶ」という仕事の実物がこれだから。
汎用のカード一覧でも同じ機能は作れるが、**「接して並ぶ」「印が付く」という構造が、
この仕事の速度と記憶に直結する**。

### 2.2 色（トークン）

地色は**中立**（彩度 0 に近い）。絵の色判断を歪めないため、暖色に寄せない。

#### 表（おもて）— 昼のカタログ。明るい部屋で使う

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--paper` | `#EFEFF0` | 画面の地（中立の灰。クリームではない） |
| `--surface` | `#FAFAFA` | パネル、ツールバー |
| `--seam` | `#C6C7CA` | フレームの継ぎ目（フィルムの素地の明るい版） |
| `--ink` | `#1A1C20` | 本文 |
| `--ink-muted` | `#666A72` | 補助（数値の単位、注記） |
| `--line` | `#D8D9DC` | 区切り線 |

#### 暗幕 — 夜の視聴。絵を見るための暗い部屋

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--paper` | `#161719` | 画面の地（青みも暖かみも足さない） |
| `--surface` | `#1F2124` | パネル、ツールバー |
| `--seam` | `#0C0D0E` | フレームの継ぎ目（フィルムの素地） |
| `--ink` | `#E7E8EA` | 本文 |
| `--ink-muted` | `#92969D` | 補助 |
| `--line` | `#2C2E32` | 区切り線 |

#### 意味の色（両テーマ共通の役割。値はテーマごとに変える）

| トークン | 表 | 暗幕 | 用途 |
| --- | --- | --- | --- |
| `--accent` | `#0F6C78` | `#54B6C2` | 操作の色。フォーカス輪、選択、リンク。**絵の上には置かない** |
| `--keep` | `#2C6B57` | `#5FA98C` | キープの印（楔） |
| `--drop` | `#93382C` | `#C9705F` | ボツの印（斜線）。**細い線と小さな面だけに使う**（大きな塗りにしない） |
| `--warn` | `#8A6410` | `#C9A03F` | 参照切れ、重複の疑い、AI の下書き判断 |
| `--focus` | `#0F6C78` | `#54B6C2` | フォーカス輪（`--accent` と同値。輪は 2px + 1px の離し） |

**色だけで意味を伝えない。** キープ＝楔（塗り）＋彩度そのまま、ボツ＝斜線（線）＋彩度 35%。
形と彩度が違うので、色覚に関わらず区別できる。

### 2.3 字

**書体は 2 つ。役割が違うので、混ざらない。** どちらも Windows に同梱されていることを実機で確認済み
（追加ダウンロードが不要。この道具はネットワークを使わずに動く）。

| 役割 | 書体 | 理由 |
| --- | --- | --- |
| 画面のすべて（UI・本文・数値） | **BIZ UDPGothic** | 日本語の画面に必要な文字が揃い、小さい字でも読み分けられる（UD＝ユニバーサルデザイン）。Windows 同梱 |
| Danbooru タグの日本語の語釈 | **BIZ UDPMincho** | 英語のタグ名と日本語の語釈を**書体の違いで対にする**。括弧を書かずに「名前 / 意味」の関係が出る |

**「括弧書きを使わない」という要求を、書体で解く。** これがこの画面のタイポグラフィの中心的な仕掛けである。

- 使える太さは限られる（実機で確認）: UDPGothic は 400 / 700、UDPMincho は 500 のみ。
  **存在しない太さ（600 等）を指定しない。** 階層は太さではなく大きさと余白で作る。
- 数値は `font-variant-numeric: tabular-nums` を指定する。**ただし BIZ UDPGothic は `tnum` を持たない**
  （監査 C1（実行込みのやり直し）で実測。「1111111111」75.59 px 対「9999999999」91.17 px＝揃わない。
  `font-feature-settings: "tnum"` でも同じ）。**数値のセルだけ書体を `BIZ UDGothic`
  （同じ一族の等幅版。実測 60 / 60 px）にする**（`apps/gui/styles.css` の `td.cell.num`）。
  以前ここに書いていた「`ch` 単位の固定幅」は**代替にならない**（点検 D10）。seed は **20 桁**あり
  （上限は `0xFFFFFFFFFFFFFFFF` = 18446744073709551615）、揃わないと読めない。`num` の幅は 20 桁が収まるだけ取る。

#### 字の尺度（段階。比ではなく、大きさごとに決めた 5 段。`--paper` からの相対ではなく固定 px）

| 名前 | 大きさ / 行間 | 用途 |
| --- | --- | --- |
| `caption` | 11 / 16 | フレームの番号、件数、状態の語 |
| `small` | 12 / 18 | 補助情報、タグの語釈、来歴の表 |
| `body` | 13 / 20 | 既定。一覧の 1 行、ボタン、入力 |
| `lead` | 15 / 24 | まとまりの見出し、要求の文 |
| `title` | 20 / 28 | 画面の見出し |
| `num` | 13 / 20 | 数値（tabular-nums、右寄せ、20 桁が収まる固定幅） |

- 大きさは**比で決めていない**（1.25 倍のような公比は無い）。11 / 12 / 13 / 15 / 20 の **5 段**を、
  それぞれの用途に合わせて個別に決めた。だから用途が変われば 1 段だけ動かせる（他の段を巻き込まない）。
  `num` は段ではなく数値のための別指定（大きさは `body` と同じで、右寄せと等幅数字だけが違う）。
- 本文の行長は **80 文字未満**。来歴の表は横に広いので、値の列だけを広げ、説明文は折り返す。
- 見出しの上に小さなラベル（eyebrow）を置かない。**全大文字を使わない。**
- 1 つの見出しの中で一部の語だけを強調しない（色・斜体・別書体にしない）。

- **行＝フィルム 1 本。** 行の中のフレームは**隙間なく接する**（境目は `--seam` の 1px）。
  行と行の間は 16px 空ける。これで「紙の段組み」ではなく「フィルムが並んでいる」に見える。
  `▤` は横長のコマ、`▯` は縦長のコマ（幅は絵の縦横比で決まる。§4.1）。
- **高さは密度で決まり、幅は絵ごとに違う。** `密 140px` / `普 200px` / `疎 300px` は**行の高さ**である。
  1 行のフレーム数は、幅を足していって入るところまで（§4.1）。
- 右の詳細は**畳める**（畳むと絵が広がる）。既定は開いている。
- 左の入れ物は畳める。既定は開いている。

#### まとまりレビュー（決定の画面）

「1 枚選ぶ」という仕事なので、**選ばれた 1 枚が大きい**。並べて等分にはしない（等分は比較の画面でやる）。

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 同じ指示で出した候補（8 枚）        エージェントの要求 ・ AI の推し: 3 番   ✕  │ 44px
├───────────────────────────────────────────────────────────────────────────────┤
│                                   ┌───────────────────────┐                   │
│                                   │                       │                   │
│                                   │        選択中の 1 枚   │                   │
│                                   │                       │                   │
│                                   └───────────────────────┘                   │
│   3 番 ・ 未判断   seed 338134650120909 · steps 10 · cfg 1.0 · er_sde          │
├───────────────────────────────────────────────────────────────────────────────┤
│  [1]▤ [2]▯ [3]▤ [4]▤ [5]▯ [6]▤ [7]▤ [8]▯      AI の推しに印                 │ 88px
├───────────────────────────────────────────────────────────────────────────────┤
│  ボツの理由 [ 構図・アングルが違う ▾ ]  キープの理由（任意） [ 意図どおり ▾ ]   │
│  [ この 1 枚に決める ]  [ 全部ボツ ]  [ あとで ]  [ 選んだ 1 枚を拡大で開く ] │
└───────────────────────────────────────────────────────────────────────────────┘
```

- **理由は 2 つに分ける**（P6-1b の監査 B1）: **「ボツの理由」**（`applies_to=reject`。ボツにする枚に
  **必須**）と **「キープの理由（任意）」**（`applies_to=keep`）。`decide` は「1 枚に決めたときは
  **その枚のキープ理由**をまとまりの理由として写す」ので、**キープの理由を選ぶと要求の
  `response.reason_code_id` / `reason_label` が埋まる**（エージェントが `wants: ["reason"]` で
  求めても答えられる）。選ばなくても決められる（任意）。
- 選択中の 1 枚の下に**来歴の 1 行**（`モデル · seed · steps · cfg`。監査 C3。`compare.js` の
  キャプションと同じ作り。選択が変わったときだけ 1 枚ぶん引く）。

- **`#/group/<id>` は P6-1b で実体化した**（P5 は一覧・拡大・比較だけを作った。点検 A2）。
  要求の一覧の「開いて決める」からここへ入り、決めると要求が閉じる（設計 `p6-design.md` §5.1b）。
- **注記の入口をここに置く**（点検 C5。前回の点検 C13 の未解決点）: 「**選んだ 1 枚を拡大で開く**」で
  `#/asset/<id>` へ移り、そこで印を付ける。**印を付けてから決める**のが本筋
  （判断の後に付けても `response.annotations` には入るが、先に付ける方が意図が伝わる）。
- **語は「あとで」**（まとまりレビューでも同じ語。**「保留」は使わない**。点検 C6）。
  判断の取り消しは**「判断を消す」**、削除の取り消しだけ「取り消す」。

- フィルムストリップは**隙間なく接する**（同上）。選択中のフレームだけ `--accent` の上辺 2px。
- **AI の下書き判断**はフィルムストリップのフレームに `--warn` の小さな点、見出しに「AI の推し: 3 番」。
  エージェントの理由は詳細パネル（または要求の一覧）で読める。
- 「全部ボツ」でも**理由を必ず選ばせる**（既定の理由を 1 つ用意する）。
- **`policy='all_reject_only'` のまとまりでは「この 1 枚に決める」を無効にする**（P6-1b の監査 C6。
  押すと API が 422 を返し、その文言がそのまま画面に出てしまう）。理由は `title` に書く。
- **判断の語は日本語**（`selected` / `all_rejected` をそのまま出さない。監査 C5）:
  「決定済み（1 枚に決めた）」「決定済み（全部ボツ）」。
- 決定すると `--accent` の細い線が選択から理由の欄へ流れ、記録されたことを示す（140ms、1 回だけ）。

### 2.5 原則

1. **絵以外を静かにする。** 影・角丸・グラデーションを使わない。面は 3 段（地・パネル・継ぎ目）だけ。
2. **状態は絵に出す。** 彩度と印で示す。バッジを並べない。
3. **数字は揃える。** seed・steps・cfg は右寄せと等幅数字。目で桁を追えるようにする。
4. **1 か所だけ強くする。** 強い色は `--accent`（操作）と印の 2 色だけ。他は灰。
5. **割り込まない。** エージェントの要求は件数と印で知らせ、画面を奪わない。
6. **失敗と空を案内にする。** 何が起きたか、どう直すかを書く。謝らない。

### 2.6 自己点検（汎用の既定に見えていないか）

作った案を、**どんな題材でも出てくる手**と突き合わせて点検し、直した。

| 汎用の手 | この案 | 判定 |
| --- | --- | --- |
| クリーム色の地＋セリフの見出し＋テラコッタの差し色 | 地は**中立の灰**（`#EFEFF0` / `#161719`）。見出しは**ゴシック**。テラコッタに近い `#93382C` は**ボツの細い斜線にだけ**使い、大きな面には使わない | 回避 |
| 黒に近い地＋蛍光の差し色 1 色 | 地は `#161719`（青でも緑でもない中立）。差し色は鉱物系の青緑 1 色で、蛍光ではない | 回避 |
| 罫線だらけの新聞風・角丸ゼロ・密な段組み | 罫線で囲まず、**フレームが接する**構造にした（フィルム）。段組みではなく行＝フィルム | **一度これに寄ったので直した**（下記） |
| 同じ角丸と薄い影のカードを並べる | カードを使わない。角丸も影も無い | 回避 |
| 全大文字のラベル、中黒で繋いだメタ情報、`—` で繋いだラベル、`→` を付けたリンク | 使わない。ラベルは普通の文、メタ情報は表か空白区切り | 回避 |
| 明示的な理由なく番号を振る（01 / 02 / 03） | 番号は**キー操作と順序に対応する情報**としてのみ使う（`1`〜`8`）。節番号や装飾には使わない | 条件付きで使う |
| 小さいデータラベルに等幅書体 | 等幅書体を使わず、**UD ゴシック＋等幅数字**にした | 回避 |

**直した点（重要）**: 最初の案は「1px の罫線で区切った密な格子」で、これは新聞の段組みと同じ手だった。
**フレームが隙間なく接して行を作る**（行間だけ空ける）ことに変え、罫線を「フィルムの素地」に読み替えた。
この変更で、構造が**題材から来ている**と言えるようになった。

**削ったもの（引き算）**: フレームのホバー影、ホバーでの拡大、グラデーションの帯、
件数を数える数字のアニメーション、統計パネル（どの理由が多いか等）。**判断の速度に寄与しないため。**

## 4. 部品

### 4.1 フレーム（一覧とフィルムストリップの単位）

**高さは密度で固定し、幅は絵の縦横比から決める。** 本物のベタ焼きがコマの縦横比を保ったまま並ぶのに
合わせる。幅はコマが崩れないよう**高さの 0.5〜2.2 倍**に収め、収まらないときは `object-fit: contain` で
余白を入れて**全体を出す**。**`cover` は使わない（何も切り取らない）。**

```
┌──────────────┐┌────────┐┌────────────────────┐
│              ││        ││                    │
│        ③     ││   ④    ││          ⑤         │
│              ││        ││                    │
└──────────────┘└────────┘└────────────────────┘
   横長            縦長         超横長（2.2 倍で頭打ち）
```

| 寸法 | 決め |
| --- | --- |
| 高さ | 密度（`密 140px` / `普 200px` / `疎 300px`）。**値は行の高さ**（§5） |
| 幅 | `高さ × 絵の縦横比`。`高さ × 0.5` 〜 `高さ × 2.2` に制限 |
| 収め方 | `object-fit: contain`。余白は `--seam`。**切り取らない** |
| 番号・印 | フレームの内側の四隅。幅が狭いときは番号を右上へ逃がす（番号と楔は重ねない） |

- フィルムストリップ（まとまりレビュー）も同じ規則。**高さは 88px 固定、幅は絵ごと。**
- 行の中のフレームは**隙間なく接する**（境目は `--seam` の 1px）。行と行の間だけ 16px 空ける。
- **なぜ `cover` をやめたか。** 768×1360 の絵を正方形のコマに `cover` で入れると、上下あわせて **44% が切れる**。
  切れるのは画面の端、つまり**手・足・背景の窓**で、「破綻（体・関節・結合）」や「左手の形」
  「背景の窓の位置」という**ボツの理由と要求の条件がまさにそこにある**。1 枚あたりの判断は数秒なので、
  切れた分を拡大で見直す回数はそのまま積み上がる。題材（ベタ焼き）を取るなら、**コマの縦横比も一緒に取る**。
- 幅が 2.2 倍を超える超横長（パノラマ）と、0.5 倍を下回る超縦長だけは頭打ちにする。
  頭打ちにした分は余白になるが、**切り取るよりは良い**（判断は絵の全体で行う）。

| 状態 | 見た目 |
| --- | --- |
| 未判断 | そのまま。番号だけ |
| キープ | 右上に `--keep` の楔。彩度はそのまま |
| ボツ | 画像の彩度 35% ＋ 左上から右下へ `--drop` の 1px 斜線 |
| 選択中 | 上辺に `--accent` の 2px。フォーカス輪は出さない（選択と混ざるため） |
| 要求あり | 左下に `--accent` の小さな点 |
| AI の推し | 左下に `--warn` の小さな三角 |
| 重複の疑い | 右下に `--warn` の小さな四角 2 つ重ね |
| 参照切れ | 画像の代わりに灰の面と「見つかりません」。枠は `--warn` の破線 |
| 読込中 | 灰の面（骨組み）。回る輪は使わない |

- タグは**一覧に出さない**（詳細と拡大だけ）。これは利用者の指定。
- ホバーで拡大しない。影を付けない。**押した瞬間に状態が変わる**（楽観的更新）。

### 4.2 来歴の差分表

- 行＝項目、列＝画像。列の見出しは番号（タイルと対応）。
- 「違う行」を上に、「同じ行」を下に畳む（`同じ 12 件 ▾`）。
- 差分の強調は**値の文字を太くする**（`700`）だけ。地色を塗らない（絵の隣で色が騒ぐため）。
- 数値は `num`（右寄せ・等幅数字）。増減は `10 → 20` と書く。矢印は差分の意味があるので使ってよい。
- プロンプトは語単位の差分。追加は下線、削除は取り消し線。**色だけで示さない**。
- 表の位置は下に固定。高さはドラッグで変える。

### 4.3 注記（矩形と楕円）

- 拡大の画面で、`注記` を押すと描ける。ドラッグで矩形、`Shift` + ドラッグで楕円。
- 座標は**0〜1 の割合**で持つ（画像の大きさが変わっても使える）。
- 描いた直後にメモの入力を出す。1 領域に 1 つのメモ。
- 注記の一覧を右の列に出す。押すとその領域へ寄る。消せる。
- 書き出し: 座標と文の JSON、および**囲んだ範囲ちょうど**の切り出し画像（余白を付けない）。
- `--accent` の細い実線で描く。半透明の塗りは使わない（絵を隠すため）。

### 4.4 要求のカード（要求の一覧）

```
┌────────────────────────────────────────────────────────────────────┐
│ 同じ指示で出した候補（8 枚）                       3 分前           │
│ 見てほしいこと: 左手の形 / 背景の窓の位置                          │
│ AI の推し: 3 番   「手が素直で、窓の位置も合っている」              │
│ [ 開いて決める ]   [ あとで ]   [ 断る ]                           │
└────────────────────────────────────────────────────────────────────┘
```

- 「開いて決める」でまとまりレビューへ入る。**決定すると要求は閉じる。**
- 「断る」には一言を要求する（エージェントが次の手を決められるように）。

**P6-1b で決めたこと**（要求の一覧 `#/requests` の実装。設計 `p6-design.md` §5.1・§5.2・点検 C6）:

- 既定は **`open` だけ**、新しい順。状態は URL に持つ（`#/requests?state=all` で履歴も出る）。
- カードに出すもの: `ask`（見出し）／「見てほしいこと」＝`conditions`／`origin`（小さく）／
  **AI の推し**（`ai.pick_asset_id` が何番目かと `ai_note`）／依頼からの経過（`3 分前`）／枚数／状態。
- 状態の見え方:
  - `open` … 既定。ボタンは **「開いて決める」「あとで」「断る」**。
  - `done` … 「この要求は閉じました（3 番に決めました）。エージェントがここを読みます。」
  - `declined` … `decline_note` を出す（誰が何と言ったか）。
  - `superseded` … **「同じ対象の新しい要求で差し替わりました。前の要求はここに残っています。」**＋
    新しい要求へのリンク（`state=all` のときだけ出る）。
- **「あとで」は何も書かない**（既読の概念を作らない。カードは開いたまま）。
- カードを押すと**その場で詳細を開く**（`#/requests?open=<request_id>`。別画面を作らない）。
  詳細には `ask` / `conditions` / `origin` / `wants` / `ai` / `group_id`（まとまりへのリンク）を出し、
  閉じた後は `response`（選ばれた枚・理由・注記の数）と `closed_at` / `closed_by` も出す。
- 空のとき: 「エージェントからの要求はありません。要求が来るとここに出ます。」（`--accent` を付けない）。
- **`ask` / `conditions` / `origin` / `ai_note` はエージェントの自由文**。**必ず `esc()` を通す**。

### 4.5 件数と通知

- 上部バーに `要求 3`（`--accent` の文字。件数が 0 なら出さない）。
- **タブのタイトルに件数を出す**（`(3) image-reviewer`）。
- タスクトレイのアイコンは、**要求があるとき**と**取り消せる削除があるとき**に形が変わる（件数は出さない）。
  メニューは「ブラウザで開く」「最近の削除を開く」「停止」の 3 つ。**ウィンドウを閉じていても取り消せる**
  ようにするため、「最近の削除を開く」（`#/pending-deletes`）を置く（取り消せる削除が無いときは選べない）。

### 4.6 最近の削除（常設）

5 分の取り消しは、この面が**いつでも見える**ことで初めて成り立つ。削除の直後に出る案内は消えてよいが、
**この面は消さない。**

```
┌────────────────────────────────────────────────────────────────────┐
│ 最近の削除                                       3 件 ・ 8.4 MB    │
├────────────────────────────────────────────────────────────────────┤
│ あと 3:12   D:\ComfyUI\output\naedoko_00401_.png       [ 取り消す ] │
│ あと 3:12   D:\ComfyUI\output\naedoko_00402_.png       [ 取り消す ] │
│ あと 3:12   D:\ComfyUI\output\naedoko_00403_.png       [ 取り消す ] │
└────────────────────────────────────────────────────────────────────┘
```

- **1 行 = `deletion_log` の 1 行（1 ファイル）。** 同じ操作で移した分は残り時間がほぼ同じなので続けて並ぶ
  （`duplicates-deletion-backup.md` §3.4）。
- 残り時間は `あと 3:12`（`分:秒`）。**毎秒書き換える。** 窓が過ぎた行は一覧から外す。
- 見出しに件数と合計バイト数を出す（削除の確認の画面と同じ数）。
- 「取り消す」は行ごと。**確認を挟まない**（戻す操作なので軽くてよい）。取り消したら 1 行で知らせる。
- 起動時に残り時間を引き継ぐ。**（点検 B5。P8-3 で確定）起動時には 1 件も消さない。**
  窓が切れていた分は**次の周期**（起動の 30 秒後）に消える（`p8-design.md` §0.6-3 が正。
  以前のこの行「起動後に窓が切れた分を消す」は逆だったので直した）。
  **消した後で知らせる**（「窓が切れたため N 件を完全に削除しました」を 1 回出す。黙って消さない）。
- 入口は 3 つ（どれも同じ面へ入る）: (a) `#/pending-deletes`、(b) ライブラリの上部バーの常設の入口、
  (c) トレイの「最近の削除を開く」。**モーダルからしか入れない状態にしない。**
- 空のとき: 「取り消せる削除はありません。」（入口は保留が 1 件も無ければ出さない）。

### 4.7 再現の判定（完全 / 近似 / 不可）と理由

> **廃止（2026-10-17。利用者の判断）**: **§4.7〜§4.12 の画面（`#/asset/<id>/recipe`・`#/recipes`）は P7 で作って消した**
> （`design.md` §16.5 と [`p7-decision.md`](p7-decision.md)。理由: PNG を ComfyUI にドラッグすればワークフローが戻るので記録は重複）。
> **以下の記述は歴史として残す**（画面はもう無い）。

条件と書き出しの画面（`#/asset/<id>/recipe`）と `#/recipes` の**見出しに 1 つだけ**出す。
**絵の上には出さない**（§2.5 の原則 2「バッジを並べない」は一覧の話。ここは条件を読む画面なので、語で出す）。

```
┌────────────────────────────────────────────────────────────────────┐
│ 再現: 近似                                                          │
│  ・当時の訳が残っていないため、訳し直して生成されます                │
│    （結果が変わる可能性があります）                                  │
│  ・LoRA の同一性は名前のみ（サイズ・更新時刻が一致しません）          │
│  ・ComfyUI の版が違います（記録 0.39.2 → 現在 0.39.3）               │
└────────────────────────────────────────────────────────────────────┘
```

| 判定 | 語 | 見た目 | 意味 |
| --- | --- | --- | --- |
| `exact` | **完全** | 墨の実線の枠（塗らない） | 生成に渡る条件がすべて揃い、記録と一致している（そのまま書き出せる） |
| `approx` | **近似** | `--warn` の破線の枠 | 書き出せるが、条件の一部が不明・不一致（**何が**を理由に出す） |
| `impossible` | **不可** | `--drop` の枠＋斜線 | 書き出せない（グラフが無い、今の環境にノード・モデルが無い） |

- **理由は `reasons[].kind` を 1 行ずつの日本語にする**（ID をそのまま出さない）。語は
  [`workflow-reproduction.md`](workflow-reproduction.md) §4.5 の 11 種をそのまま使う。

| `kind` | 画面に出す 1 行 |
| --- | --- |
| `missing` | 「生成の記録（グラフ）が残っていません。」 |
| `unresolved` | 「使ったモデル・VAE が今の環境にありません（`<名前>`）。置くと書き出せます。」 |
| `node_missing` | 「カスタムノードが入っていません（`<class_type>`）。」 |
| `version_differs` | 「ComfyUI の版が違います（記録 0.39.2 → 現在 0.39.3）。」 |
| `hash_mismatch` | 「モデル・LoRA の同一性は名前だけです（サイズ・更新時刻が一致しません）。」 |
| `measured_differs` | 「記録と実測が違います（steps 記録 20 → 現在 10）。」 |
| `text_not_captured` | 「当時の訳が残っていないため、訳し直して生成されます（結果が変わる可能性があります）。」 |
| `text_pinned` | 「L1 で書き出します。翻訳の枝を外すので、再現キーは記録と変わります（想定どおりです）。」 |
| `llm_nondeterministic` | 「L2 で書き出します。訳が変わりうるので、結果を測って合否を付けてください。」 |
| `gpu_differs` | 「GPU か dtype が違います（記録 bf16 → 現在 float32）。」 |
| `manual_step` | 「手作業の後処理を通っています（画素は当時と一致しません）。」 |

- **「完全」＝ 条件が同一であって、画素が同一ではない。** この語の意味を画面の下に 1 行で書く
  （`workflow-reproduction.md` §1）。
- 理由の一覧は長くなりうるので、**省略しない**（近似の理由はここを読むためにある）。
  ただし同じ `kind` が複数あるときは 1 行にまとめ、対象の名前を並べる。
- 判定は記録の `status` / `reasons` をそのまま出す（画面で判定し直さない）。

### 4.8 レベルの選択（L1 / L2 / L3）

書き出す前に**どのレベルで書き出すか**を選ぶ。既定は L1。

| 選択 | 名前 | 書き出すグラフ | 何が違うか |
| --- | --- | --- | --- |
| **L1** | 最終プロンプトを確定 | 当時 `CLIPTextEncode` へ渡った英文（`final_prompt`）を**リテラル**で入れ、翻訳の枝を外す | 訳が揺れない。**再現キーは記録と変わる**（ノードが 1 つ減るため） |
| **L2** | グラフごと | 元のグラフのまま（`TextGenerate` も走る） | **訳を作り直す。同じ条件でも訳が変わりうる**（`mtp`・`thinking`・dtype 次第） |
| **L3** | 自分で訳を入れる | 訳を入れる場所を空にしたグラフ。利用者が英文を入れて回す | L1 と同じく決定的。訳を人が書く |

- **L1 が既定。** 当時の最終プロンプトが分かっているときだけ選べる（`final_prompt_source` =
  `png_literal` / `reconstructed` / `manual`）。分からないときは **L2 に落ち、落ちたことを画面に出す**
  （`text_not_captured` の理由と、**L3 への入口**を同じ場所に置く。§6）。
- **L1 を「失敗」と読ませない。** L1 は翻訳の枝を外すので、**再現キーが必ず変わる**。記録のキー（元）と
  書き出しのキー（変えた後）を**別々に並べ**、差の理由を `text_pinned` と書く
  （`workflow-reproduction.md` §4.2 の注記 2・§4.9 の `recipe_export.recipe_hash`）。
- 選んだレベルは `mode`（`pin_text` / `rerun_graph` / `manual_text`）として記録に出し、
  **結果の行にも出す**（あとから「どのレベルで出した結果か」を追えるように）。
- **L2 のときは、訳が変わりうる理由を 1 行添える**（`mtp` / `thinking` / `use_default_template` /
  dtype / GPU のうち、記録と食い違うものを挙げる）。結果は必ず測って人に合否を求める（§4.11）。
- レベルは**書き出しごとに選べる**（記録は書き換えない。同じ記録から L1 と L2 の両方を出してよい）。

### 4.9 書き出しの束（attempt_id・印・フォルダ・manifest・seed の一覧）

**利用者がこのフォルダの JSON を ComfyUI のキャンバスへドラッグ&ドロップする。** それがこの画面の出口である。

```
┌────────────────────────────────────────────────────────────────────┐
│ 書き出し r7k2m4   seed 8 件   API 形式   2025-10-14 21:32          │
│ 印 repro-r7k2m4/seed-<seed>   フォルダ <data>\exports\<recipe>\r7k2m4\
│ [ フォルダを開く ]  [ manifest を読む ]                             │
│ ┌────────────────────────────────────────────────────────────────┐ │
│ │ seed-338134650120909.json   → repro-r7k2m4/seed-338134650120909 │ │
│ │ seed-998211003122.json      → repro-r7k2m4/seed-998211003122    │ │
│ │ manifest.json                                                  │ │
│ └────────────────────────────────────────────────────────────────┘ │
│ このフォルダの JSON を ComfyUI のキャンバスへドロップして Queue      │
│ seed の欄は触らず、control_after_generate は fixed のまま           │
└────────────────────────────────────────────────────────────────────┘
```

- **「フォルダを開く」でエクスプローラを開く。** アプリの中でファイル一覧を真似ない（D&D は OS の操作なので、
  実物のフォルダを出す方が速い）。選んでキャンバスへドロップする（1 つずつでも束でもよい）。
- **seed の一覧**を出す（`seed → グラフのファイル名 → 期待される出力ファイル名`）。期待値は
  `repro-<attempt_id>/seed-<seed>` の**前方一致**で書く（連番の桁数は ComfyUI 次第なので、
  完全一致を期待値にしない。`workflow-reproduction.md` §4.7.3）。
- **manifest の `notes`（検査の結果と手順 1 行）は画面にも出す。** ファイルを開かせない。
- **印（`repro-<attempt_id>/seed-<seed>`）は保存ノードの `filename_prefix` に入る。**
  これは保存先を決めるだけの値で、**再現キーから除外してある**。だから
  「**印を付けてもキーは変わらない**（＝条件は同じで印だけ違う）」と言い切れる。この 1 行を束の横に出す。
- **印を付けられないとき**（`filename_prefix` がリテラルでない、`type='output'` の保存ノードが無い、
  保存ノードが複数ある等。`workflow-reproduction.md` §4.7.1 と点検 **B9** の前提）は、
  印を付けずに書き出し、**結果は `matched_by='conditions'` の候補に落とす**。このとき §6 の文言を出し、
  「書き出しを止める」か「`SaveImage` を足す」かを利用者が選ぶ。
- **同じ記録から何度でも書き出せる。** `attempt_id` は書き出しごとに新しく発行する（衝突しない）。
  seed 違いは `attempt_id` を共有し、`seed-<seed>` で区別する。
- 記録は書き換えない（`workflow-reproduction.md` §6-5）。

### 4.10 結果の行（どの書き出しの絵か・ひも付けの根拠・指標）

**1 行 = 出てきた画像 1 枚**（`recipe_export_result`）。1 回の書き出しに複数枚ぶら下がる。

```
┌────────────────────────────────────────────────────────────────────┐
│ 結果 3 枚                     書き出し r7k2m4（seed 8 件・API 形式）│
├────────────────────────────────────────────────────────────────────┤
│ [絵] 998211003122   印で自動（marker）   同一の hash: いいえ        │
│      SSIM 0.982   pHash 距離 3   変化した画素 0.021   平均差 1.8    │
│      合否 [ 同じ ][ 近い ][ 違う ][ 失敗 ]   メモ [            ]    │
├────────────────────────────────────────────────────────────────────┤
│ [絵] 338134650120909   手で指定（manual）  ⚠ seed が書き出しと違います│
└────────────────────────────────────────────────────────────────────┘
```

- 行の左に**どの書き出しか**（`attempt_id` と seed）と、**どうやってひも付いたか**（`matched_by`）を出す。
  - `marker` = 「印で自動」。`manual` = 「手で指定」。`conditions` = 「条件が一致（人が選んだ）」。
- 指標は `same_hash` / `ssim` / `phash_distance` / `changed_fraction` / `mean_abs` をそのまま並べる。
  **定義の正は [`comparison.md`](comparison.md) §4**（ここでは再定義しない）。単位だけ添える
  （`changed_fraction` は 0〜1、`mean_abs` は 0〜255、`phash_distance` は 64bit のハミング距離）。
- **閾値を画面に出さない。** 「これ以下なら同じ」という線を引かない。**合否は人が付ける**（§4.11）。
  数値は並べるだけにする。
- **seed が書き出しと違うときは、行の先頭に `--warn` の 1 行を出す**（§6）。黙って「同じ条件の結果」として
  記録しない（`workflow-reproduction.md` §4.7.2 の対策 2）。
- **ひも付いていない結果は行を作らない。** 結果の一覧の下に**候補**として出す。候補は
  「モデル ＋ リテラルのプロンプト文 ＋ 解像度」が一致する未紐付けの画像（**seed は見ない**）。
  選ぶと `matched_by='manual'` でひも付く。入口は §6 の「この結果がどの書き出しのものか分かりません」の
  すぐ下に置く（`workflow-reproduction.md` §4.7.1 の表）。
- 元の記録も、元の画像も書き換えない。出てきた画像は**別の `asset`** として登録される
  （`workflow-reproduction.md` §4.8）。
  その画像をライブラリで開く入口をこの行に置く（キープ / ボツを付けたければ通常の判断と同じ）。
- 取り込みは監視が行う（`workflow-reproduction.md` §5）。**画面から API を叩いて生成しない。**

### 4.11 合否の入力（same / close / different / failed ＋ メモ）

```
合否  [ 同じ ]  [ 近い ]  [ 違う ]  [ 失敗 ]
メモ  [                                                        ]
```

- 語は 4 つ。**同じ（`same`）/ 近い（`close`）/ 違う（`different`）/ 失敗（`failed`）**。押した瞬間に記録する
  （楽観的更新。失敗したら戻して 1 行で知らせる。§7）。
- **これは「当時の絵と一致するか」の判断**であって、画像の**キープ / ボツ（`kept` / `rejected`）とは別**に付く。
  混ぜない（`workflow-reproduction.md` §1・§4.8）。
- メモは任意（空でも記録できる）。`failed` のときは一言を促す見た目にする（必須にはしない。
  必須にするかは**未確認**。`workflow-reproduction.md` に指定が無い）。
- 合否を変えられる。記録は**消えない形**で残る（`design.md` §14 P7 の完了条件）。
- 元の記録は書き換えない（`workflow-reproduction.md` §4.8）。結果は別の行として残る。

### 4.12 プリセットの一覧（名前・メモ・コピー）

```
┌────────────────────────────────────────────────────────────────────┐
│ プリセット 6 件    人が読んでコピーするための一覧です（適用はしません）│
├────────────────────────────────────────────────────────────────────┤
│ 夜の室内・セル調   1girl, solo, window light, …          [ コピー ] │
│ 元: naedoko_00401_.png  2025-10-14  メモ: 窓の位置が良かった        │
└────────────────────────────────────────────────────────────────────┘
```

- 出すもの: **名前・メモ・元画像・作成日時**。行ごとに置くのは**「コピー」だけ**。
- **「適用」ボタンは置かない。** 適用はしないと決めている（他のカットへの適用、エージェント向けの
  プリセット API、プリセットを条件にしたスマートフォルダは**作らない**）。
  ここは**人が読んでコピーする**ためだけの面である。理由を一覧の見出しの横に 1 行で書く
  （`workflow-reproduction.md` §4.10・§6-10）。
- コピーするのは `record_json` の値そのもの（プロンプトとパラメータ）。コピーしたら §6 の 1 行を出す。
- 「この条件に名前を付ける」は、**画像の詳細と条件の画面の両方**に置く（`workflow-reproduction.md` §4.10）。

### 4.13 タグ（2 行 1 組。P4-3 で新設）

**語は 1 行にまとめ、英語の行と日本語の行の 2 行 1 組で出す。** 語そのものの括弧は消さない
（`rem_(re:zero)` はそのまま。括弧を使わないのは**語釈の行**の話。`p4-design.md` §0.7 / §5.1）。

```
キャラ                      ← カテゴリの見出し（語が無いカテゴリは出さない）
rem_(re:zero)  [タガー] 0.993        ← 1 行目: 語・出所の印・スコア（タガーの行だけ小数 3 桁）
    レム（Re:ゼロから始める異世界生活）   ← 2 行目: 日本語の語釈（BIZ UDPMincho・--ink-muted）
一般
long_hair  [PNG] [タガー] 0.881
    長い髪
first_girl:_black_hair  [PNG] [語彙外]   ← 語彙外の印（既定の検索では出ない）
    日本語の語釈はまだありません。 [訳す]
```

- **出所の印**: `PNG`（生成に使った語）/ `タガー`（画像から読んだ語）/ `手`（人が付けた語）。
  同じ語が 2 つの出所にあれば**印も 2 つ**。`手` の印だけ `--accent`。
- **スコア**: タガーの行だけ、小数 3 桁・等幅（`num`）。`PNG` と `手` には出さない。
- **カテゴリの見出し**: `キャラ`（category 4）→ `作品`（3）→ `作者`（1）→ `一般`（0）。**語が無い見出しは出さない**
  （eva02 v3 の CSV には artist / copyright が無いので、実際は「キャラ → 一般」になる）。
  **`category` が `null` の語（語彙外＝PNG の自然文の断片）は「その他」**に入れる
  （**一般に混ぜない**。P4-3 の監査 C-4 で確認。実物では「キャラ → 一般 → その他」の 3 つになる）。
- **語釈が無いとき**: 「日本語の語釈はまだありません。」＋「**訳す**」（12px の枠ボタン）。
  語釈があるときは**出さない**。人が直した語釈には `直した` の印。
- **欄の下に必ず 1 行**: 「タガーは下ごしらえです。手の破綻などは読めません（人が見て直してください）。訳は自動です。直せます。」
- **操作**（欄の下）: 「**訳す（20 語まで）**」（見えている語のうち語釈が無いもの）／「**語を足す**」（1 行の入力。
  前方一致の候補を出す）／語ごとの「**外す**」（**`手` の行だけ**に出す）。
- **`#/tags`**（語の一覧）: 左に語の一覧（名前・枚数・カテゴリ・語釈）、右に選んだ語の語釈の確認と修正。
  上に「語で絞る（前方一致）」「表示: 語彙あり / 語彙外 / すべて」「訳す（20 語まで）」、下に「一括タグ付け」。
- **`#/jobs`**: 1 つのジョブが 1 行（状態・`done / total`・1 枚あたり・残り時間・進捗の細い帯）。
  **中断**は実行中の行にだけ。**失敗した項目**は理由つきで畳んで出し、「**もう一度**」で失敗した分だけやり直す。

## 5. 表示の切替

| 切替 | 値 | 既定 | 覚える場所 |
| --- | --- | --- | --- |
| 密度 | `密 140px` / `普 200px` / `疎 300px` | 普 | 端末ごと（`localStorage`） |
| テーマ | `表` / `暗幕` | 暗幕 | 端末ごと |
| 詳細パネル | 開 / 畳 | 開 | 画面ごと |
| 入れ物の列 | 開 / 畳 | 開 | 端末ごと |

- **密度の値（140 / 200 / 300）は「行の高さ」である。** フレームの幅はここでは決まらない。
  幅は**絵の縦横比**から決まり、高さの 0.5〜2.2 倍に収める（§4.1）。
- `疎` のときだけフレームの下に 1 行（モデル + seed）を出す。タグは出さない。
- 切替は**即座に反映**し、アニメーションを挟まない（スクロール位置が飛ぶため）。

## 8. アクセシビリティと品質の下限

1. **フォーカスが見える。** `--focus` の 2px 輪 ＋ 1px の離し。`outline: none` を単独で使わない。
2. **色だけに頼らない。** キープ＝楔、ボツ＝斜線＋彩度。要求＝点、AI の推し＝三角（形が違う）。
3. **コントラスト。** 本文は 4.5:1 以上、大きい字は 3:1 以上。`--ink-muted` は `body` 以上の大きさでだけ使う。
4. **拡大に耐える。** 200% でもレイアウトが壊れない（一覧のフレーム数が減るだけ）。
5. **動きを減らす設定に従う。** `prefers-reduced-motion` で、決定時の 140ms の流れと、
   ルーペを開くときの 120ms の拡大を止める。
6. **読み上げ。** フレームには「3 枚目、キープ、女の子1人、1girl」のように、
   番号・状態・タグ（日本語）・タグ（英語）を並べたラベルを付ける。
7. **キーボードだけでも主要な操作ができる**（補助だが、詰まらない）。
8. **戻る・再読込に耐える。** すべての画面の状態は URL にある。

## 9. 速度の作り

「速く動く」は画面の設計の一部（`design.md` §12）。画面側で守ること:

1. **描くのは見えている分だけ。** 仮想グリッド（**行の高さは密度で固定、幅は絵の縦横比で決まる**。
   行単位で入れ替える。§4.1）。
2. **画像は遅延して読む。** `loading="lazy"`、`decoding="async"`、`width`/`height`（または `aspect-ratio`）
   を先に指定してガタつきを消す。`IntersectionObserver` で先読み（画面の 1.5 画面分）。
3. **先に小さい絵。** 一覧は 256px サムネだけ。拡大で 1024px。**原本は開かない。**
4. **判断は楽観的。** 押した瞬間に印を変え、`POST /api/reviews` を裏で送る。失敗したら戻す。
5. **進みは押し出しで受ける。** `GET /api/events`（SSE）で走査・ハッシュ・タグ付け・監視の進みを受ける。
   1 秒ごとのポーリングはしない。SSE が切れたときだけ 5 秒間隔のポーリングに落ちる。
6. **届いた画像を無駄に描き直さない。** 一覧の更新は差分で当てる（行単位）。
7. **切替はアニメーションを挟まない**（密度・テーマ）。
8. 目標値は `design.md` §12.1（一覧の初回 300ms / 追加 100ms、比較 8 枚 400ms）。
