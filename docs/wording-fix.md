## 1. 規則 3 つ（`docs/frontend-design.md` §6.1 の冒頭に入れた文）

> 利用者から「中国感がある」と言われて監査したところ、**中国語の語彙は 1 件だけ**（`gloss.py` の「語釈の模型」＝
> 中国語の「模型」）で、**本当の原因は次の 3 つの癖**だった。**1 件ずつ直すのではなく、規則として決める。**
>
> 1. **中黒「・」は名詞の対にだけ使う。文と文、メタ情報と文は読点「、」か句点「。」で繋ぐ。**
>    - よい例（名詞の対）: 「写真・その他」「段 1・2」「人数・人物」「キープ / ボツ」。
>    - 「3 枚 ・ 8.4 MB」→「3 枚、8.4 MB」（**表の列として並べるなら区切り記号を書かない**）。
>    - 「最近の削除 3 ・ あと 3:12」→「最近の削除 3（あと 3:12）」、「おすすめ: 3 番 ・ 画素数が最大」→「おすすめ: 3 番（画素数が最大）」。
>    - **文を中黒で繋がない**（「…外すだけ・段 2 はゴミ箱・段 3 は…」ではなく「…外すだけです。段 2 は…。段 3 は…。」）。
>    - **半角の中点 `·`（U+00B7）は使わない**（全角の「・」か「、」）。`—` で繋いだラベルも使わない（文は「。」で切る）。
> 2. **英語の内部値と開発者の記法を、利用者に見える文に出さない。**
>    - `kind` / `source` / `wants` / ジョブの `kind` / `state` などの**値は日本語のラベルの地図を通す**
>      （`apps/gui/jobs.js` の `STATE_LABEL` と同じ形。地図に無い値は「その他（値）」）。
>    - **バッククォートと `**太字**` の記法を HTML と端末の文に書かない**（強調は鉤括弧「」か、HTML の `<b>`）。
>    - **設計書の節番号（`design.md` §7.3.1）・工程の番号（P6 の画面）・監査の記号（監査 B1）を出さない。**
>    - **技術用語は残す**: pHash・WAL・SQLite・ABI・sha256・seed・VAE・LoRA・cfg・denoise など。
> 3. **「枚」「物」を名詞に立てない。**
>    - 「枚」は**助数詞だけ**。名詞には**「画像」**を使う。
>    - 「物」は**漠然とした対象なら仮名の「もの」**。**指す物がはっきりしている語はそのまま**
>      （「消す物を確かめる」「別物として確定」）。**同じ意味で仮名と漢字を揺らさない。**

**この 3 つを正として、`frontend-design.md` §6 の行と実装を合わせた。**
§6 の自己矛盾（§5-1「中黒で繋いだメタ情報を使わない」と書きながら、同じ §6 の行が「3 枚 ・ 8.4 MB」を定めていた）は
**規則を §6.1 に 1 つ決めて、行の方を直す**ことで解消した（§6 の末尾にも「行と規則が食い違って見えるときは §6.1 が正」と書いた）。
