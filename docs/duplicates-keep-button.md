## 2. なぜ要ったか（利用者の混乱の原因）

- `state.view` の `keep` は**ラジオで変えられる**のに、**行の強調とラジオのチェックにしか使われていなかった**。
- `pickedIds()` は `on`（チェックボックス）しか見ず、**「削除へ回す」も「まとまりにする」も `keep` を見ていなかった**
  ＝**ラジオは飾り**だった。だから「何に使うの」と聞かれ、「これだけ残して消すボタン」を求められた。
- ラジオの語も `title` だけで、**画面には見えていなかった**（`frontend-design.md` §6 の文言表にも無かった）。

## 4. 二重の守り（`keep` の 1 枚はチェックが付いていても渡さない）

1. **入口で外す**: 群ごとのボタンは `keepOutIds(i)` でその群の `keep` を除いて組む。
2. **渡す直前に外す**: `toDelete(ids)` が `withoutKept(ids)` を通す（**全群の `keep` を落とす**）。
   下部バー（チェックの経路）から `keep` が混ざっても、ここで必ず落ちる。
   → **実データ（19 群）で「全部選ぶ」を押すと 53 枚に印が付き、渡るのは 34 枚**（19 枚の `keep` は 1 枚も渡らない。§7）。

## 5. 検査をどう足したか（`gui_smoke.mjs`。**相手の節には触っていない**）

- **ラジオの「残す」が見える**: `<label class="dup-keep" …><input type="radio" …><span class="dup-keep-word">残す</span></label>`
  の形であること（**`title` の中だけでは通らない**）＋行の数（3 枚）だけ出ること。
- **群ごとのボタン（押す検査）**: ラジオで `keep` を `a1` に変える → `keepOutIds(0)` が `a2,a3` →
  押すと `#/pending-deletes?ids=a2,a3`（**`a1` を入れない**）・`POST` は 0 回。
- **1 枚の群**: 1 枚だけの応答に差し替えて、**描いた HTML の `disabled`** と `title` の理由を見て、
  **押しても道が変わらない**ことも見る（作り物の DOM は `disabled` を届けてしまうので、`onClick` 側の守りも見る）。
- **下部バー（二重の守り）**: 3 枚チェックしても表示は「選んだ **2** 枚」＋「残す 1 枚は渡しません。」、
  渡るのは `a1,a3`（`a2` を入れない）。**既存の 1 検査の期待値は `a1,a2,a3` → `a1,a3` に変えた**（仕様の変更そのもの）。

## 10. 申し送りと設計の穴

1. **申し送り: `frontend-design.md` の「削除へ回す入口」を 3 つ → 5 つに直した。**
   数え漏れていたのは**重複の整理の下部バー**（前からあった）と**今回の群ごとのボタン**。
   他の画面に入口を足すときは**この行も直す**（入口の一覧が正）。
2. **申し送り: 下部バーの枚数は「渡す枚」に変わった。** 「選択 N 枚」（チェックした枚）とは
   `keep` の分だけ違い得る。**違いがあるときだけ**「残す 1 枚は渡しません。」を出す。
3. **申し送り: 「全部選ぶ」は `keep` もチェックする**（チェックは「印」で、渡す枚ではない）。
   渡さないことが 1 行で見えるので誤解はしないはずだが、**「keep 以外を全部選ぶ」に変える**案は残っている
   （利用者の判断。今回は仕様のとおり**複数選択の経路を残した**）。
4. **設計の穴 1: 群ごとのボタンの `title` はホバーでしか読めない。** 1 枚の群でなぜ押せないかは
   その場では見えない（`disabled` の見た目だけ）。**群ごとに 1 行の説明を出す**案はあるが、
   群が 19 もある実データでは行が増えるので、今回は `title` に置いた（`frontend-design.md` の仕様どおり）。
5. **設計の穴 2: `index.html` の説明の行（`dup-help`）は新しいボタンに触れていない。**
   「ここでは消しません（選んだ画像は削除の確認へ渡します）」で**意味は通る**が、
   「群ごとのボタン」という語は出ない（担当の外なので触っていない）。
6. **設計の穴 3: 群ごとのボタンは「その群の `keep` 以外」を渡す**ので、**同じ群の枚が
   べつの群にも入っている**ことは無い（群は素集合）が、**群をまたいで同じ `keep` を渡さない**ことは
   `withoutKept` が全群で見て守っている。**入口を足すときは `toDelete` を通す**こと（`deleteHref` を直に呼ばない）。
7. **相手の作業への影響は 0**。相手の検査（段ごとの語・「用意」を利用者に見せない）は**そのまま通っている**
   （`gui_smoke` 365 ok の中に含まれる）。
8. **`gui_layout.mjs` は触っていない。** 群ごとのボタンとラジオの「残す」を**本物の Chrome で守る検査**を
   `tools/gui_layout.mjs` に足すなら、`--screen duplicates` の `MEASURE_DUP` / `PRESS_DUP` に
   1 項目ずつ足す形になる（今回は自分の脚本で確かめた。§7）。
